# 计划评分协议（2026-11-06）

目的：回答"叫上 WorkBuddy 一起想，到底比我自己想好多少"——而不是"两个模型谁更好"。

## 硬顺序（否则作废）

1. 我先独立写一版，存 `self-<时间>.md`；
2. 再让 WorkBuddy 答**同一道题**（新会话，`sessionContinuity: "off"`）；
3. 两版**随机编号 A/B**，评分时隐藏来源与成本，只看内容；
4. 记一行到 `scores.jsonl`，揭盲后记成本。

顺序反了就等于用它的框架写我的答案，分数没有意义。

## 从第一份贡献计划吸收的规则（2026-11-06 19:17，它赢 4:1）

那次它给的版本比我的更硬，以下四条并进协议：

1. **模板不计分**：六段齐全、候选更多、篇幅更长，都只是"门槛"，不加质量分——
   否则套模板就能刷分。
2. **先冻结再看结果**：权重、阈值、样本量在看数据之前定下，看到结果再换指标就等于自欺。
3. **编造事实要封顶**：出现"编造我们的代码细节/违反硬约束"，该条总分封顶（5 维 25 分制下最多给 10 分），
   不允许被漂亮格式抵消。
4. **保留负样本 + 报分布**：超时、失败、被驳回的计划都进账；报告看**中位差值与胜平负**，不只报均值。

样本量：**攒到 12 对**再谈趋势（一次约 7–18 积分，12 对大致 84–216 积分，先想清楚值不值）。


## 五个维度（各 1–5）

| 维度 | 问的问题 |
| --- | --- |
| 可执行性 | 第一步是不是今天就能动手，还是"再研究研究" |
| 反例质量 | 说的是"这方案在哪失效"，还是泛泛的"注意风险" |
| 信息诚实 | 不知道的标了没有，有没有编造本项目的细节 |
| 信息密度 | 删掉客套话还剩多少 |
| 我会照做 | 最直接的一票 |

## 任务层：三个字段（2026-11-06 补，来自 19:40 那份计划）

上面五维评的是**计划文本**。可文本好不等于任务做成——一条计划可以写得漂亮，任务照样失败。
所以账本还有三个**任务层**字段：

| 字段 | 取值 | 回答什么 |
| --- | --- | --- |
| `--outcome` | `pass` / `partial` / `fail` | 任务最后验收通过了吗 |
| `--rework` | 次数 | 中间人工返工了几次 |
| `--minutes` | 分钟 | 这件事一共花了多久 |

这三个字段只在**有记录时**参与统计（没记的不算成 0），报表会分别显示通过/部分/未通过、返工均值、耗时均值。

判断"协作值不值"，看的是 `任务结果 + 返工 + 耗时 + 积分` 这一组，而不是五维总分。

## 成本单独记

成本（积分/耗时）只进报表，**不参与打分**——否则"免费"会替你做判断。

## 命令

```powershell
node tools/score.mjs add --task "要不要拆插件" `
  --self .collab\self-20261106-1916.md `
  --plan "C:\Users\donghao\.dsh\codebuddy-bridge\plans\20261106-1916.md" `
  --score-self 4,3,5,4,4 --score-plan 3,2,5,3,3 `
  --cost 7.23 --adopted yes --note "它的第一步更具体"

node tools/score.mjs report
```

`--adopted` 取 `yes` / `partial` / `no`，这是中层指标（"我是真的照做了吗"）。
底层指标是**预言命中率**：计划里点名'这方案会怎么失效'，后来真发生了吗——这个靠回看，不进脚本。

## 已知局限

- 样本小的时候（< 5 次）任何均值都是噪声；
- 评分人是使用者本人，标准会漂移——所以固定维度、固定顺序；
- "我 vs 它"天然混入模型差异，无法分离，只能接受并在结论里写明。
